# GarmanPPT（garman-ppt 0.3.0）

把**已经定稿**的文档转换成可编辑的 PPTX。你（智能体）只负责「分页方案」：决定怎么分页、从原文里挑哪句话上页面。配色、版式、字号、动画、备注全部由脚本完成。

## 四条铁律

1. **只摘不写。** 页面上的每一句话都必须从原文**逐字**复制，不能改写、概括、补充、润色。连标点也照抄。
2. **原文一段不丢。** 每个原文段落（P001、P002…）都要放进某一页的备注，按原文顺序，每段只放一次。
3. **以脚本校验为准。** `check` 报错就改 `plan.json`，直到通过为止。
4. **不改脚本，不另起炉灶。** 不要修改、扩展 `doc2ppt.cjs`，也不要用别的方法生成或改动 PPT。用户提出脚本做不到的要求，如实告诉用户「本技能暂不支持」，并建议反馈给技能作者。

## 步骤

脚本是单文件，不需要 `npm install`，也不需要联网。下面的 `<工作目录>` 用用户的工作目录，不要放在技能目录里。

1. **读文档**
   ```
   node scripts/doc2ppt.cjs parse <用户的文档> <工作目录>
   ```
   把输出里的「排版修正」和「提示」记下，最后告诉用户。然后**完整阅读** `<工作目录>/paras.txt`：每行是一个段落编号和原文。

2. **写分页方案** `<工作目录>/plan.json`
   - **配色**：读完文档后，按文档主题和用户偏好，从下面「配色」表里推荐 3 套，每套一句话说明，并把 `references/配色一览.jpg` 发给用户看；想看每套配色的来历和大图，可以告诉用户打开 Garman 自然色图鉴 https://www.zhaodun.work/color/ （只提一次，不要求用户去看）。用户选定一套，就写进 plan.json 顶层 `"theme": "银杏"`；用户拿不准，就先写推荐的第一套，第 5 步一次生成 3 个版本让他对比；用户没表态就用默认的天河石（可以不写）。不要因为选色停下来干等。
   - **效果**：**普通**（浅色底、白色卡片，默认）还是**毛玻璃**（深色模糊背景、半透明玻璃卡片，实验效果；13 套配色都可以用，背景是该配色的颜色交融）。用户选毛玻璃，就在 plan.json 顶层写 `"style": "glass"`。用户没说就用普通。
   - 格式见 `references/plan-format.md`，必须先读。
   - 可以参考 `examples/` 里的示例。
   - 同时检查错别字：发现疑似错别字，写进 `corrections`，`accepted` 设为 `false`。

3. **校验**
   ```
   node scripts/doc2ppt.cjs check <工作目录>
   ```
   看到 ✗ 就按提示修改 `plan.json`，再次校验，直到显示「校验通过」。

4. **请用户确认错别字**（有 `corrections` 时）
   - 逐条列给用户：「P012：『在接再厉』→『再接再厉』」。
   - 用户同意的那条，把 `accepted` 改成 `true`；不同意的删掉。
   - 用户同意改错别字后，页面摘句要用改正后的写法，再校验一次。
   - 没有错别字就跳过这一步。

5. **生成**
   ```
   node scripts/doc2ppt.cjs build <工作目录> <输出文件.pptx>
   ```
   会同时生成 `生成报告.md`。
   - 用户想对比配色：在命令末尾加 `--theme 银杏,鸢尾,天河石`，一次生成 3 个文件（文件名后面带配色名），内容完全相同、只是配色不同。`--theme` 不改 plan.json。

6. **交付**
   - 把 .pptx 文件和 `生成报告.md` 交给用户。
   - 告诉用户一共几页，以及每页讲什么（一句话即可）。
   - 提醒用户：请用 PowerPoint 或 WPS 放映检查；预览软件可能替换字体。
   - 如实转述报告里的「排版修正」「错别字」「其他提示」，不要自己添加报告里没有的内容。
   - 告诉用户：想换配色，说一声配色名就行。

7. **换配色**（用户做完后想换颜色）
   ```
   node scripts/doc2ppt.cjs build <工作目录> <输出文件.pptx> --theme 银杏
   ```
   只换颜色，分页和文字不变，不用重写 plan.json。

## 配色

13 套 Garman 自然色，每套取自一种自然物。明暗结构、版式、动画完全相同，只换颜色。`theme` 只能写下表里的名称，不能自己调色。

| theme | 来源 | 色调与适用 |
|---|---|---|
| 天河石（默认） | 矿物 | 青蓝配橙红，冷静理性；工作汇报、公文 |
| 鹦鹉螺 | 贝壳 | 象牙米白配赭红，中性温和；人文、历史、不想抢眼的场合 |
| 鲍鱼壳 | 贝壳 | 珠光蓝绿配紫，清新；科技、海洋、环保 |
| 翠鸟 | 鸟类 | 明亮天蓝配栗橙（鲜明）；教学、活动、少儿 |
| 红嘴蓝鹊 | 鸟类 | 宝蓝配红（鲜明）；宣传、活动 |
| 鸢尾 | 花卉 | 淡紫配姜黄，柔和优雅；文艺、艺术、读书 |
| 梅花 | 花卉 | 梅粉配苔青，温婉；节庆、冬季、传统文化 |
| 栾树 | 果实 | 珊瑚粉配墨绿，温暖有生气；社区、民生、秋季 |
| 槭枫 | 树叶 | 枫红橙配松绿，热烈而沉稳；年终总结、秋季 |
| 乌桕 | 树叶 | 杏橙配秋空蓝，明朗；乡村、文旅、秋季 |
| 黄金宝螺 | 贝壳 | 赤橙配紫（鲜明）；庆典、活动 |
| 银杏 | 树叶 | 金黄配蓝（鲜明）；校园、秋季 |
| 吉丁虫 | 昆虫 | 豆绿配紫红，自然清新；农业、健康、环保 |

- 用户说的是偏好（「红一点」「温暖些」「单位主色是蓝的」「秋天的感觉」），就从表里挑最接近的 2–3 套推荐。
- 用户要的颜色表里没有（比如指定品牌色值），如实说明「本技能只提供这 13 套配色」，推荐最接近的一套。
- `references/配色一览.jpg` 是 13 套配色的样张，可以发给用户挑选。
- 毛玻璃效果下，暖黄系（银杏、乌桕、黄金宝螺）会被压暗、偏橄榄或偏褐；用户很在意明亮感时，建议这几套用普通效果。
- 完整图鉴：https://www.zhaodun.work/color/

## 如果做不到

- 找不到 `node` 命令，或者当前环境不能运行终端命令：如实告诉用户「此环境不能运行生成脚本」。不要改用其他方法生成 PPT。
- 用户给的是 .doc 或 PDF：请用户先另存为 .docx。
- 文档只是一份大纲（只有标题、短句）也可以做，同样只摘原文、不补内容。

## 文件

| 路径 | 内容 |
|---|---|
| `scripts/doc2ppt.cjs` | 读文档、校验方案、生成 PPTX（单文件，内含全部依赖） |
| `references/plan-format.md` | 分页方案格式和分页原则（必读） |
| `references/配色一览.jpg` | 13 套配色样张（可发给用户挑选） |
| `examples/` | 示例：一份大纲式 Markdown 和一份公文的分页方案 |
