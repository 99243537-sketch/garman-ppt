# 更新：排队取结果，解决 524 超时（2026-10-20）

这个包取代 ppt-web-fix1.zip（那个不用装了）。不动 doc2ppt.browser.js、.env、ppt-planner.service、Nginx。

## 步骤

```
cp ppt/app.js ppt/index.html /www/www.zhaodun.work/ppt/
cp -r ppt/preview /www/www.zhaodun.work/ppt/
sudo cp ppt-planner/app.py ppt-planner/prompt.md ppt-planner/.env.example /opt/ppt-planner/
sudo systemctl restart ppt-planner
curl -s http://127.0.0.1:8796/api/health
```

health 应返回 `"running": 0, "queued": 0`。端口还是你改的 8796（从 .env 读取，不受影响）。

最后在 Cloudflare 控制台对 `https://www.zhaodun.work/ppt/` 做一次 Purge Cache（自定义清除这个网址即可），避免有人拿到旧页面。

## 改了什么

- 新接口 `POST /api/jobs` 立刻返回任务号，浏览器每 3 秒 `GET /api/jobs/<id>` 取结果，单个请求都在一秒内返回，不再碰 Cloudflare 的 100 秒限制。旧接口 `/api/plan` 保留，给还缓存着旧页面的人用。
- 分页结果只在内存里保留 10 分钟，不写硬盘；原文段落用完即丢。
- 新增限额（都有默认值，不用改 .env；要调就照 .env.example 加）：
  - `MAX_CONCURRENT=3` 同时调用 MiniMax 最多 3 份，其余排队，页面显示前面还有几份
  - `GLOBAL_DAILY_LIMIT=200` 全站每天总次数
  - `MAX_QUEUE=20` 排队太多时提示稍后再来
  - 同一个人同时只能做 1 份；在做的也先算进当天次数，失败不扣
- 访客识别改用 Cloudflare 传来的 `CF-Connecting-IP`（原来的 X-Real-IP 拿到的是 Cloudflare 节点 IP）。仍然只存哈希。
- 包含上一个修复包的内容：中文错误码、截断识别、修正次数成功后才计。

## 如果 MiniMax 报限流

usage.db 里会出现 `upstream_error:HTTPError`。如果多，在 .env 里把 `MAX_CONCURRENT` 调成 2，再重启。

## 回退

旧版 app.py / app.js / index.html 先备份一份；有问题换回去重启即可。
